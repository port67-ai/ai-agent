# Render activation — live foundation

Use the existing **ai-agent** Render service tracking **port67-ai/ai-agent main**. Portal: https://ai-agent-7k04.onrender.com/portal. No hosting migration is required.

1. In Render service → Environment, copy the variable names from config/factory.env.example. Generate a random session secret of at least 32 characters and operator password of at least 16 characters directly into protected environment settings. Never commit or paste credentials into chat. Set PORT67_PUBLIC_ORIGIN=https://ai-agent-7k04.onrender.com. Leave launch/provider flags false initially.
2. For the single-process local store, attach a persistent disk mounted at /var/data (Render disks require a compatible paid service). Set PORT67_STORAGE=local and PORT67_DATA_DIR=/var/data/port67-factory. Only that mounted path persists; the app filesystem is ephemeral. Use one instance/process. Set PORT67_PERSISTENCE_CONFIRMED=true only after checking the actual mount. Demo storage may remain disposable and separate.
3. Alternatively select PORT67_STORAGE=firebase with a dedicated PORT67_FIREBASE_PROJECT_ID, database and service-account JSON. Do not reuse the legacy booking project. Review client-deny rules, service-side access and least-privilege IAM before PORT67_FIREBASE_SERVER_ONLY_CONFIRMED=true. Explicit PORT67_FIREBASE_USE_ADC=true selects an available runtime identity and ignores JSON; Render does not supply a Google identity automatically. The adapter is not cloud-verified.
4. Save/deploy, inspect Workspace setup in the synthetic producer demo, then enable PORT67_LIVE_ENABLED=true when the origin, credentials and durable store are ready. Sign into the real producer workspace. Create a non-sensitive test project, restart/redeploy and confirm it survives before onboarding customers. Disable live access again if persistence fails.
5. Add PORT67_OPENAI_API_KEY in protected settings. Set a Responses-compatible model tested for web research in PORT67_RESEARCH_MODEL; enable PORT67_RESEARCH_ENABLED only after budget review. For schema-based drafting set PORT67_SYNTHESIS_MODEL (or the research-model fallback) and PORT67_SYNTHESIS_ENABLED=true. A ready configuration is not proof of provider/model compatibility. The default shared project invocation limit is 12; this is not a currency budget.
6. In a public-data test project, authorise the current brief, run research, review cited sources, draft insights, accept/reject them, draft direction, review/share it, and obtain customer approval before production. Revoke authorisation to stop accepting future results; it cannot undo data already sent or charges incurred. Research and drafting remain optional; manual workflows continue.

No Firebase project, paid provider invocation, disk or Render secret was provisioned in this implementation: credentials were unavailable. Do not claim live integration verification until the above smoke tests are recorded. Shared producer authentication, bearer invitations, snapshot storage, missing monetary budget enforcement and limited media formats remain MVP constraints. Per-person accounts/MFA, rendered video and phase-two analytics/publishing remain future work.
